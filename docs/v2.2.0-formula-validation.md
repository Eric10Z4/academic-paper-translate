# v2.2.0 公式、原生编译与收尾核验

核验日期：2026-10-15。真实翻译通过 Hermes 调用本地配置的 CPA，使用 Windows、Python 3.13、MiKTeX XeLaTeX。此记录区分程序校验、视觉检查和语言质量，不把生成 PDF 当成验收通过。

## 发现的原因

SCORE（arXiv:2203.04413）有可用 TeX 源码，但此前解析器拒绝正常的 `\looseness=-1` 整数赋值，因而进入 PDF 降级。原文公式和算法源码本身完整。PDF 引擎会把分数的字形与横线分开移动；该论文第 4 页的横线包含独立图像遮罩，不能仅依靠矢量绘图列表检测。算法步骤被重组为自然段，缩进和逐行结构丢失。

其他原生阻断包括受支持范围不足的模板命令、入口歧义及编译依赖问题。网络/SSL 错误、HTML 错误响应和多主文件工程都不能作为“论文没有源码”的证据。

## 修复范围

- 严格解析并冻结 `looseness` 整数赋值，恢复时终止 TeX 数字扫描；整体冻结行内、展示和 `ensuremath` 公式。算法主体保持原文，仅翻译 caption。
- 增加受限重音、关键词、致谢及会议元数据支持；保持不安全宏定义、动态语法和占位符篡改的拒绝规则。
- 重试向模型提供完整性错误和所需标记顺序，不放宽校验。
- 区分源码获取、响应格式、主文件选择和编译失败。缺包报告给出文件名；旧 arXiv 时间戳可正常打包。
- 仅在日志明确显示 microtype 的非原生字体 `XeTeXglyph` 冲突时，在隔离副本中有界重试，关闭 protrusion。成功的设置保留供源码包重编译；其他编译错误照常处理。
- 固定 pdf2zh-next 2.9.0 / BabelDOC 0.6.2，保留未分配线条，并扫描薄线及图像遮罩作为风险页提示。扫描是启发式，不能证明公式完整。
- PDF 降级默认 `review_required`；所有产物要求实际查看全部中文页面。绑定三 PDF 散列的视觉记录通过后，`--finalize` 删除本次运行目录和散列匹配的已登记源码 ZIP，保留 PDF、记录和缓存。失败、未检查、活动进程及路径越界均不清理；未知文件和旧失败运行不做无差别删除。

SCORE 首轮缺少 `nicefrac` / `lipsum`，补齐本地依赖后复验。接着实际触发 microtype 兼容重试与旧 Times 字体兼容重试，最终完成 XeLaTeX → BibTeX → XeLaTeX → XeLaTeX。`--disable-installer` 仍保留，技能不会静默忽略缺包。

公式 (7) 的约 16.2 pt 超宽伸入空白页边，放大观察完整可见，没有裁切或遮挡；SimSun small-caps 替代警告未造成可见缺字。页码对应的内容随中文重排改变，左右按页号配对不等于段落对齐。

语言质量边界：复核发现 SCORE 中文第 1 页有一处省略号及语序衔接不顺。公式和版式核验通过不代表全文逐句语义审校通过；本版不宣称所有句子准确或任意模板均可处理。

## 公开发布与复验

真实 SCORE 测试由调用方提供匹配的原始源码与英文 PDF，不在仓库附上论文、私有配置、备份或本机日志：

```bash
python -B tests/run_formula_acceptance.py --workspace /path/to/isolated-workspace \
  --case score --source-project /path/to/score-source --original /path/to/score.pdf
```

按 [SKILL.md](../SKILL.md) 通过 Hermes 运行真实翻译。发布合并保留既有的来源身份核验、完整数值保护、包命名空间及 CI 隔离适配。GitHub Actions 只运行确定性回归与安装包检查，不调用真实翻译服务；当前运行结论以 Actions 为准。

**纯 PDF 公式识别尚未通用修复。** 本版修复了已确认的原生误降级与编译阻断，并阻止未验收的坏 PDF 被直接报为成功。
