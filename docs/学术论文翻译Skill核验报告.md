# 学术论文翻译技能核验报告

核验日期：2026 年 10 月 12 日。

**结论：当前版本尚未达到规范中的硬性期望。** LaTeX 优先、本地 XeLaTeX 编译、中文宏包注入和双语拼页的架构方向已经落实；但“表格绝对冻结”“公式不可变”“引用无损”“四件套齐全才算成功”和“失败自动承接”都存在可复现缺口。适合继续开发和小范围人工检查，不适合作为无需逐篇核验的论文批量归档工具。

本次以桌面的《学术论文翻译Skill改造与核验规范.md》为验收基准，完整阅读技能目录内全部 8 个 Python 文件、3 份提示词、SKILL.md 和 AUDIT_SPEC.md。没有修改原技能。测试均在独立工作目录中运行；真实模型请求仅使用自造短句和微型论文。

定向核验包含 33 项检查：30 个预先构造的边界或失败场景复现了缺陷，3 个基础对照正常。这些场景归并为下文的主要问题，不代表 30 个互相独立的根因，也不能当作真实论文的失败率。

技能根目录：`<HERMES_SKILLS>/academic-paper-translate`。以下代码位置均相对于此目录；证据包包含文件 SHA-256 清单，可确认所审版本。

**对六项硬性要求的判断**

| 要求 | 判断 | 直接依据 |
| --- | --- | --- |
| 纯翻译、完整保留语义和结构 | 未达标 | 普通正文会因空行、注释、相邻公式被整段跳过；模型输出无结构和完整性验证 |
| 表格数值和方法名绝对冻结 | 未达标 | 表格内部空行、表格数据由子文件引入时，数据被送入模型 |
| 引用占位符无损保护 | 部分实现，未达标 | 简单引用可往返还原，但可选参数和星号形式漏保护；占位符丢失或重复不报错 |
| 本地中文编译、自愈和引用收敛 | 部分实现，未达标 | 能实际编译中文；成功判定不检查退出码；xeCJK 自愈没有真正切换宏包 |
| 三 PDF 加完整源码 ZIP | 未达标 | 缺双语 PDF 仍成功；拼页按较短文件截断；源码 ZIP 丢弃可能必需的 `.bbl` |
| 源码优先、平滑降级 | 部分实现，未达标 | 存在编译失败后的降级分支，但翻译异常绕过它；降级产物未校验、未标准化命名 |

**已经确认能工作的部分**

- 8 个 Python 文件可以解析，主入口 `--help` 正常。
- 本机能找到 XeLaTeX、BibTeX 和 uv。直接编译中文双栏微型工程成功，公式和表格可以清晰显示。
- 本地 CPA 的模型列表可访问，包含指定模型，真实短句翻译调用成功。
- 无内部空行的简单表格用例只向模型发送 caption，数据没有外泄。
- 简单 `\cite{key}` 和 `\ref{label}` 的占位符还原正常。
- 真实微型论文经“模型翻译 → 本地编译 → 源码打包”得到中文 PDF，正文、表题、引用和表内数值在该样本中正常。
- 在隔离测试目录补齐 PyMuPDF 1.28.2 后，同一微型工程完整生成了三 PDF 和源码 ZIP；中英文及双语版各 1 页。它证明依赖齐全时简单工程能跑通，不改变上述边界场景的失败结果。

这些结果证明基础路线可行，不能证明任意论文均满足绝对保真。

**一 必须优先修复的数据完整性问题**

**1．表格冻结没有覆盖完整环境，最高准则已被突破。**

位置：`scripts/zotero_translate.py:228–229, 294–325, 358–366`。

代码先按空行拆分文件，再检查每段是否包含 `\begin{table}` 或 `\begin{tabular}`。没有跨段维护环境状态。因而表格开头和数据行一旦被空行分开，后续数据行就会被当成自然语言段落。

复现输入：

```latex
\begin{table}
\begin{tabular}{lr}

MethodAlpha & 90.3 \\

\end{tabular}
\caption{Result values}
\end{table}
```

测试适配器确实收到 `MethodAlpha & 90.3 \\`；适配器故意将数值改为 `90.375` 后，程序直接写回，没有拒绝。这里的数值修改是受控测试，证明程序允许篡改，不代表真实模型每次都会篡改。

另外，`\input{rows}` 引入的数据文件会被独立遍历翻译，父文件中的表格保护无法传递到子文件。

修复：先解析完整环境和文件引用关系，再提取自然语言；冻结区从原始字节片段回填。对除允许修改的 caption 文本外的表格内容做精确比较，不一致则拒绝产物。仅增加环境名称不能修好这一问题。

**2．数学表达式和部分代码环境实际未冻结。**

位置：`scripts/zotero_translate.py:220–225, 308–325, 333–335`。

`$...$`、`\(...\)`、`\[...\]` 会随段落直接进入模型。测试将 `$x_i=90.3$` 中的数值改为 `99.9`，程序接受并保存。`algorithm` 容器也不在代码环境清单里，测试中整段进入模型。即使是列出的公式环境，内部空行也存在与表格同类的问题。

修复：统一识别行内数学、展示数学、公式环境和代码区；冻结原文，翻译后核验。这应是程序保证，不能只靠提示词“不要修改公式”。

**3．正文存在静默漏译。**

位置：`scripts/zotero_translate.py:294–318`。

已复现三种情况：正文与公式环境在同一空行块中，整块跳过；注释行开头后紧接正文，整块跳过；从导言区到正文没有空行时，整份文件被当作导言区跳过。带较长可选参数的 `\caption[...]{...}` 也会因 `find_command_positions` 中的十字符限制漏译。

修复：对正文、标题、caption、宏参数分别提取，不能用“包含公式则整段跳过”代替结构解析。输出翻译覆盖率和漏译片段清单。仅检查是否有中文不足以证明全文完整。

**4．占位符只有替换，没有完整性约束。**

位置：`scripts/zotero_translate.py:248–256, 270–273, 333–335`。

简单形式受保护，但 `\citep[see][p. 2]{key}`、`\citet*{key}`、`\ref {label}` 不匹配现有正则。测试还证明：模型返回中完全丢掉占位符，或把一个占位符重复两次，程序都会接受。

修复：解析宏及其可选参数、星号、空白；每段生成不可碰撞的占位符。回填前核对标识集合、次数及受约束的相对顺序，禁止未知或残留占位符。校验失败时重试或保留原段并报告失败。

**5．模型生成的 TeX 特殊字符会改变源码含义。**

位置：`adapters/cpa_adapter.py:34–42` 与 `scripts/zotero_translate.py:334–355`。

真实调用把以下原文：

```text
The proposed method achieves an accuracy of 90.3 percent. See \cite{audit2026}.
```

译成了：

```latex
所提出的方法取得了 90.3% 的准确率。参见 \cite{audit2026}。
```

新产生的 `%` 未被转义，在 TeX 中会把后面的同一行内容变成注释。因此占位符即便正确还原，引用仍会在排版结果中消失；若发生在 caption 内，还可能吞掉闭合括号。这是本次真实模型返回，不是模拟故障。

修复：只让模型返回自然语言片段，并按片段上下文安全转义新产生的 `%`、`&`、`#`、下划线等字符。不要对整份 TeX 盲目全局转义，否则会损坏原有语法。

**二 编译与交付流程中的严重问题**

**6．编译失败可以被判定为成功，旧 PDF 可以冒充新译文。**

位置：`scripts/latex_compiler.py:122–139, 169–171`。

当前只判断预期文件是否存在且大于 1000 字节，不检查编译退出码、不确认文件是本轮新生成的。测试预放一个旧 PDF，再让所有 XeLaTeX 调用返回失败，函数仍返回“XeLaTeX 编译成功”。BibTeX 失败也被忽略。

修复：在独立干净构建目录编译；检查每轮退出码，验证 PDF 可打开且属于当前运行；检查引用未定义、缺字和致命错误。参考文献后端应按工程需要选择 BibTeX、Biber 或已有 `.bbl`，不能无条件调用后忽略结果。

**7．xeCJK 自愈分支实际上没有切换宏包。**

位置：`scripts/latex_compiler.py:57–58, 109–110, 166–169`。

首次注入 `\usepackage[UTF8,scheme=plain]{ctex}` 后，自愈再次调用注入函数，函数看到 `\usepackage[UTF8` 就提前返回。结果仍然保留 ctex，没有加入 xeCJK。自愈轮只运行一次 XeLaTeX，也没有重新完成参考文献和交叉引用收敛。

修复：保存注入前版本；重试时替换自己管理的宏包区块，而不是追加或因已有宏包直接退出。每个候选配置均完成完整编译与验收，保留两次错误记录。

**8．双语合成会截掉较长文档的尾页，且按页码拼接不等于内容对齐。**

位置：`scripts/latex_compiler.py:194–207`。

循环上限是 `min(len(orig), len(mono))`。例如英文 10 页、中文 12 页时，只合成 10 页，中文最后两页不会进入双语 PDF。这与完整翻译相冲突。

补充真实 PDF 测试：英文 1 页、中文 2 页时，合成函数返回成功，输出只有 1 页，中文第 2 页缺失。另一个测试中原 PDF 的 1 个链接在合成后变为 0 个，说明页面视觉复制也不等于交互功能被完整保留。

修复：至少按较大页数生成，缺失侧明确留空并注明；报告页数差。进一步按章节或段落锚点建立对应关系。即使页数相同，重新排版后第 i 页的内容也未必对应原文第 i 页。

**9．缺少必需产物也会宣告圆满完成。**

位置：`scripts/zotero_translate.py:444–468`；`scripts/latex_compiler.py:182–184`。

主流程没有检查双语合成的布尔返回值。没有原版 PDF 时直接跳过合成，却仍返回成功。真实微型工程在 PyMuPDF 缺失的运行环境下只得到 original、中文单语和源码 ZIP，程序仍返回 True 并打印“论文翻译与归档圆满完成”。

修复：归档前统一校验清单、文件可读性、页数、论文身份与翻译状态；区分完整成功、部分完成、降级完成和失败。任一必需产物缺失，不能报告完整成功。CLI 应以非零退出码传播失败；当前 `main()` 丢弃返回值，已复现错误信息伴随退出码 0。

**10．源码 ZIP 不一定能重编译，本地原始工程还会被覆盖。**

位置：`scripts/latex_compiler.py:158–164, 232–233`；`scripts/zotero_translate.py:354–366, 428–438`。

所有 `.bbl` 都被当作垃圾排除。对于只有 `.bbl`、没有 `.bib` 的工程，这会丢掉必要的参考文献来源；自愈还会直接删除它。测试确认这两种行为。

输入本地目录时，程序直接在该目录改写每个 `.tex` 并注入宏包。测试确认原始英文文件被覆盖。翻译中途失败时，会留下半翻译工程。

修复：复制只读原工程到独立工作副本；保留工程所需 `.bbl`，只删除本轮确定生成且可重建的缓存；最终 ZIP 解压到新目录重新编译，作为归档验收。输出 ZIP 位于工程目录内时还需排除输出自身，避免把归档文件打包进自身。

**三 调度和兜底尚未形成可靠闭环**

**11．降级只覆盖部分失败，且没有最终产物规范化。**

位置：`scripts/zotero_translate.py:438, 469–483`；`scripts/pdf_runner.py:17–48`。

正文翻译超时或 API 出错会从线程池向外抛出，主流程没有捕获，既不保存失败状态，也不进入 PDF 降级。测试模拟 TimeoutError 后确认降级函数调用次数为 0。caption 出错则只打印消息、保留英文，最后仍可能整体成功。

PDF 兜底只根据子进程退出码判断成功，没有验证中文及双语 PDF 是否产生，没有重命名为规范名称，也没有超时。测试在子进程返回 0、目录空无一物时仍得到 True。实际 pdf2zh-next 翻译质量没有在本轮做全篇验收。

修复：各阶段使用明确的状态和可恢复错误类型；有限重试后按可用原版进入降级；验收并标准化兜底产物；记录降级原因和质量等级。降级流程可继续提供可读译文，但不能沿用 LaTeX 冻结区校验通过的承诺。

**12．若干对外宣称的入口行为没有实现。**

位置：`scripts/zotero_translate.py:43–52, 394–425, 488–508`。

- 直接输入论文标题时，没有调用标题检索函数。真实测试输入 “Attention Is All You Need”，检索调用次数为 0，立即失败。
- 路径中包含 arXiv 编号时，编号识别在本地 PDF 判断之前执行。本地 `2301.12345.pdf` 被当成编号输入，联网失败后丢失了现成 PDF 的兜底机会。
- CLI 选择 deepseek 或 ollama 时，由于未传入配置，`get_adapter()` 最终仍构造 CPAAdapter；测试确认两个选项均无效。
- 输出目录已有 `original.pdf` 时，换一个 arXiv ID 也不重新下载或核对来源。测试确认旧原文会继续参与处理，存在原文与新源码不属于同一篇论文的风险。

修复：优先识别存在的本地路径；补全标题检索和候选匹配；正确实例化所选适配器；为输出目录保存论文 ID、版本和原文摘要散列。所谓“全网检索”目前仅有有限的 arXiv 逻辑，应收窄说明或真正实现多来源检索。

**四 其他值得一并修复的问题**

- **依赖不可复现。** 目录没有依赖清单或版本锁定。默认 Anaconda Python、Hermes 自身 Python 和本次使用的文档运行时，在初次检查时均无 `fitz`。uv 兜底也未锁定 pdf2zh-next 版本。建议增加启动自检、依赖锁定和明确运行入口；先验证依赖再开始耗时翻译。
- **Windows 日志解码错误。** 真实完整流程出现多次 `UnicodeDecodeError: 'gbk' codec ...`。`latex_compiler.py:122–130` 的 `text=True` 使用了系统默认编码。建议采集字节日志后按适当编码容错解码，并保存原始字节，避免错误信息丢失。
- **长文和限流处理不足。** 三个适配器基本上是单次 HTTP 请求。没有针对 429、临时服务错误和截断返回的有限重试，也未检查 `finish_reason`；无分块长度约束、术语一致性检查或断点恢复。
- **源码包解压缺少显式边界。** `zotero_translate.py:155–156` 直接 `extractall`。在本次 Python 3.12.14 的受控测试中，包含 `../escaped_audit.tex` 的模拟源码包把文件写到了目标解压目录的上一级；测试目标仍在隔离工作区内。不同 Python 版本的默认过滤策略不同，应显式启用安全过滤并限制路径、符号链接、体积和文件数，不能依赖宿主默认值。
- **凭证写在多处源码和文档中。** 应移到环境变量或本地配置，避免归档和分享审查材料时传播。报告不重复该凭证。
- **文档与行为冲突。** SKILL.md 要求零总结，末尾却要求维护“核心创新点”导读；三份独立提示词也没有接入 CLI 选择。建议统一实际支持的功能和承诺。

**五 建议的修复顺序与验收门槛**

| 顺序 | 工作 | 必须达到的验收结果 |
| --- | --- | --- |
| 1 | 原工程隔离、结构解析、表格及公式冻结 | 跨空行、嵌套、跨文件输入均不会把冻结内容送入模型；冻结区回填逐字一致 |
| 2 | 占位符校验、输出转义、覆盖率检测 | 丢失、重复、未知标记和新产生的危险特殊字符被拒绝；漏译被明确列出 |
| 3 | 编译成功判定、自愈、参考文献 | 非零退出码与陈旧 PDF 不能通过；真正切换宏包；无未解析引用和必要资源丢失 |
| 4 | 双语全页合成和产物验收 | 页数不等不丢页；任何必需文件缺失不能标记完整成功；源码解压重编译通过 |
| 5 | 输入路由、依赖、降级、断点恢复 | 标题、本地编号 PDF、后端选择正确；网络失败可恢复；降级结果有独立质量标记 |
| 6 | 真实模板和长文回归 | 覆盖 CVPR、NeurIPS、ICML、ACM、多文件工程、超宽表格、复杂公式和长参考文献 |

不建议先投入精力继续修改提示词。最高优先级是把“绝对冻结”和“完整成功”从提示词、日志文案变成可验证的程序条件。

**对规范本身的两点修订建议**

第一，保留论文版式结构、双栏几何、公式和图表源内容是合理目标；“翻译后页码、图表位置、段落分页 100% 与英文相同”不能由加入 ctex 或几个断行参数保证。应将内容保真、几何保留、视觉溢出和页间对应分开验收，允许明确记录的重排。

第二，“三 PDF 加源码 ZIP”应区分有源码和无源码场景。原文根本没有 TeX 源码时，无法提供真实的翻译 TeX 工程；应交付三 PDF 与清晰的处理清单，而非为了凑数伪造源码 ZIP。有源码但编译失败时保留未编译 ZIP，并明确标记。

**本次核验的证据边界**

隔离测试中，模型和编译失败场景使用可控替身，以验证程序是否能阻止错误；真实 CPA 调用和本地中文编译另行执行。双语截页和链接缺失用真实 PyMuPDF 与 PDF 文件复现。一个小工程成功不等于顶会模板兼容性已验证。本次没有重跑既往 62 篇论文，没有验证所有第三方模板，也没有把 pdf2zh-next 的实际全篇翻译质量视为已通过。新增的 PyMuPDF 仅位于审查工作目录，没有更改 Hermes 或系统 Python 的依赖。
